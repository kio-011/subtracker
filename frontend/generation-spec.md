# Спецификация генерации: как агент строит фронтенд

Порядок работы агента. Каждая задача выполняется отдельно, после неё результат проверяется (поведение, внешний вид, тесты), потом следующая. Входные материалы: `spec.md`, `scenario.md`, `design-system.md`, `ui-library.md`, макет (ссылка в README), `AGENTS.md`.

## Правила для всех задач

- Перед кодом агент называет, какие компоненты из `ui-library.md` он переиспользует и что создаёт заново.
- Внешний вид берётся с макета и из `design-system.md`. Если решение отличается от макета, агент говорит об этом, макет обновляется.
- После задачи запускаются `npm test`, `npm run lint`, `npm run build`. Задача считается готовой только когда всё проходит.
- Работающий результат показывается на настоящем API (бэкенд запущен), а не только в тестах.

## Шаблон запроса к агенту (по лекции)

```text
Реализуй задачу <номер и название> по спецификации frontend/spec.md (разделы <…>),
макету (кадры <…>) и дизайн-системе frontend/design-system.md.
Сначала назови компоненты из frontend/ui-library.md, которые ты переиспользуешь,
и файлы, которые создашь. Не пиши собственных кнопок, полей и диалогов,
цвета и шрифты бери только из переменных темы. После реализации запусти
npm test, npm run lint, npm run build и покажи результат.
Критерии приёмки: <правила из spec.md с номерами>.
```

## Проверка результата человеком

1. Запустить бэкенд и фронтенд, пройти сценарий: регистрация, вход, неверный пароль, добавление подписки с ошибкой и без, список.
2. Сверить экраны с макетом по каждому состоянию.
3. Пройти сценарий только с клавиатуры.
4. Сузить окно до 360px.
5. Двойным кликом и повторным Enter убедиться, что запрос один (вкладка Network).
6. Запустить `npm test`.
